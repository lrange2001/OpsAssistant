# 权限模式与审批

五种模式(`/mode <名>` 命令或 Ctrl+Shift+M 循环切换,切换时有 toast 提示;每会话独立记忆;设置里可固定选择)。**生成中也可以随时切换**(`/mode plan`、Ctrl+Shift+M、`/mode` 查看当前模式均不打断回复),新模式从下一回合生效:

| 模式 | 文件写 | shell 命令 | ops 双工具(ops_type / ops_read) |
| --- | --- | --- | --- |
| **plan** | 禁止 | 一律要确认 | 恒 auto,无审批卡 |
| **build**(默认) | 安全操作自动执行;危险命令(rm、sudo、git push 等)要确认 | 安全操作自动执行;危险命令(rm、sudo、git push 等)要确认 | 恒 auto,无审批卡 |
| **edit** | 自动执行 | 一律要确认 | 恒 auto,无审批卡 |
| **yolo** | 全部自动执行(拒绝规则仍然生效,慎用) | 全部自动执行(拒绝规则仍然生效,慎用) | 恒 auto,无审批卡 |
| **ops** | 不出现(该模式的工具表只带 ops 双工具,文件读写经终端 cat) | 不出现(一切命令经终端,见 09 章「ops 模式」) | **恒 auto、无审批卡**:ops_type 只放命令、绝不代回车,ops_read 只读输出——执行权在你的回车(回车即人审)。进入需至少一个在线 SSH 终端 |

ops 双工具不受四模式分级约束——它们只把命令放进终端输入行 / 只读输出,真正的执行与风险都在你回车那一步;完整的 ops 循环(在线终端清单、执行纪律、放命令后强制收轮等)只在 ops 模式下生效,详见 09 章「ops 模式」。

### 审批卡片

需要确认时消息流里出现权限卡,列出要执行的操作和风险等级(high 红 / medium 黄 / low 绿),下面是**编号选项列表**(单击选中、再单击应答;也可用键盘:↑↓/Tab 移动、Enter 确认、数字键 1-6 直接应答)。ops 模式的两个工具(ops_type / ops_read)恒 auto,**不产生审批卡**——人审体现在终端里的回车(见 09 章「ops 模式」):

1. **Allow once** — 这次允许
2. **Always allow** — 允许并记住规则,下次自动执行。shell 命令会显示两个范围 chips:**精确**(命令主键,如 `git push`)或**前缀**(首词,如 `git *` 匹配一切 git 命令),点选后再应答;其他工具按工具名记忆
3. **Allow this session** — 本会话内不再询问(记在会话上,不进全局配置;之后同类请求直接自动放行并继续执行)
4. **Allow this project** — 本项目(当前工作目录)内不再询问,规则只在同目录的会话生效
5. **Deny** — 拒绝。行下方有**反馈输入框**:填一句"接下来该怎么做"(如"用 git clean 代替"),会以「用户反馈:」带给模型;Enter 提交、Esc 交还焦点
6. **Always deny** — 拒绝并记住,以后不再问

记忆的规则在 设置 > 工具与权限 里查看、增删;规则行有**项目**一列(留空 = 全局生效,填目录 = 仅该项目内生效)。规则类型:`command`(命令主键,如 `git push`)、`command_prefix`(前缀,如 `git`)、`tool`(工具名)。
